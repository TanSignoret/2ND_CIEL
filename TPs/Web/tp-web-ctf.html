🎯 Le principe

Ce TP est un CTF (Capture The Flag) :

Chaque défi cache un flag, une chaîne de caractères de la forme CIEL{...}. À vous de la trouver en explorant la page : le code HTML, les styles CSS, le JavaScript, les cookies, l'URL et les échanges réseau.

Tous les défis sont sur cette page même : c'est elle que vous allez disséquer.

⚖️ Éthique et légal — à lire avant de commencer
  • Le « hacking » est une pratique qui consiste à comprendre comment un système fonctionne pour en trouver les failles.
    Sans autorisation, c'est un délit (article 323-1 du Code pénal : accès frauduleux à un système de traitement automatisé de données).
  • Ici, la cible est cette page de TP : l'autorisation est explicite. Ailleurs, elle ne l'est jamais par défaut : tester le site de l'école, d'un commerce ou d'un camarade sans accord écrit = attaque.
  • C'est exactement le métier du pentester : chercher les failles avec autorisation pour qu'elles soient corrigées. En entreprise, on travaille toujours avec un mandat écrit.
01

Votre boîte à outils : les DevTools

Briefing

Tous les défis se résolvent avec les outils de développement du navigateur, ouverts avec F12 (ou Ctrl+Maj+I). Prenez 10 minutes pour explorer chaque onglet avec votre binôme :

Onglet Ce qu'on y trouve Défis concernés
Éléments Le code HTML réel de la page, modifiable en direct 1, 2, 3
Console Exécution de code JavaScript, messages d'erreur 4, 5, 6
Réseau Tous les échanges entre le navigateur et le serveur 8
Application Cookies, stockage local, cache 6
Barre d'adresse L'URL et ses paramètres (après le ?) 7
💡 Méthode de travail

Pour chaque défi : notez le flag ET la manipulation qui l'a révélé (2 phrases). Un flag sans explication ne compte pas : on cherche des techniciens qui comprennent, pas des cliqueurs chanceux. Les défis sont indépendants : si vous bloquez, passez au suivant.

Les défis

≈ 3h — menu libre
🟢 Défi 1

Le premier flag est quelque part dans le code source de cette page… mais invisible à l'écran. Ouvrez le code avec Ctrl+U ou l'onglet Éléments et fouillez les commentaires HTML.

Flag trouvé : ____________________ · Méthode : ____________________

🟢 Défi 2

Le flag ci-dessous existe dans la page, mais un attribut l'empêche de s'afficher. Trouvez-le dans l'onglet Éléments et modifiez le HTML en direct (double-clic sur l'attribut ou clic droit → « Modifier le HTML ») pour le rendre visible.

Voici la zone secrète :

Le flag est : CIEL{dom_modifie_avec_f12}

Flag trouvé : ____________________ · Qu'avez-vous modifié ? ____________________

🟡 Défi 3

Un flag est défini dans les styles CSS de la page (dans le contenu d'un pseudo-élément ::after). Mais l'élément HTML ci-dessous ne porte pas la bonne classe, donc rien ne s'affiche. Lisez les styles, puis ajoutez la bonne classe à l'élément dans l'onglet Éléments.

Cet élément cache quelque chose…

Flag trouvé : ____________________ · Quelle classe avez-vous ajoutée ? ____________________

🟡 Défi 4

Ce petit formulaire vérifie un mot de passe… mais la vérification se fait dans votre navigateur, donc le code est visible. Lisez la fonction verifierCoffre dans le code source : le mot de passe y est caché, mais à l'envers. Trouvez-le, tapez-le, et le flag s'affichera.

🔐 Coffre-fort numérique :

Flag trouvé : ____________________ · Quel était le mot de passe et comment l'avez-vous trouvé ? ____________________

🟡 Défi 5

Le développeur a caché le flag dans un tableau de codes de caractères, mais sa fonction d'affichage ne marche plus (ouvrez la Console : il y a une erreur !). Corrigez la fonction dans l'onglet Console, ou reconstruisez le flag vous-même avec String.fromCharCode(...).

Flag trouvé : ____________________ · Comment avez-vous procédé ? ____________________

🟡 Défi 6

Cette page dépose un cookie à chaque chargement : acces=invite. La zone ci-dessous ne s'ouvre que pour un cookie acces=admin. Trouvez le cookie (onglet Application, ou document.cookie dans la Console), puis modifiez sa valeur et rechargez la zone.

🔒 Accès refusé : vous êtes « invité ».

Flag trouvé : ____________________ · Quelle valeur de cookie avez-vous posée et comment ? ____________________

🟡 Défi 7

La zone ci-dessous refuse l'accès… mais son code source révèle qu'elle lit un paramètre dans l'URL. Lisez le code (fonction verifierURL), trouvez le paramètre attendu et sa valeur, puis ajoutez-les à l'URL de la page (après un ?) et rechargez.

🔒 Accès refusé : paramètre d'autorisation manquant.

Flag trouvé : ____________________ · Paramètre et valeur ajoutés : ____________________

🔴 Défi 8

Au chargement, cette page a déjà échangé deux messages secrets avec un « serveur ». Rien ne s'affiche à l'écran : ouvrez l'onglet Réseau, rechargez la page, repérez les requêtes, et examinez leur réponse. Attention : l'un des deux messages est un faux flag posé par l'administrateur…

Les échanges ont eu lieu au chargement de la page…

Vrai flag trouvé : ____________________ · Comment avez-vous éliminé le faux ? ____________________

💎 Bonus

Pour les binômes en avance : inventez votre propre défi. Cachez un flag dans cette page (commentaire, style, JS, cookie…) et préparez un petit indice écrit. Échangez votre défi avec un autre binôme : chacun doit résoudre celui de l'autre. Le défi le plus malin rapporte 30 pts au binôme qui l'a créé ET à celui qui le résout.

03

Compte rendu à déposer sur Pronote

≈ 30 min — obligatoire

Un compte rendu par binôme, à déposer sur Pronote, contenant :

  • En-tête : noms du binôme, date, score total obtenu (additionnez les points des défis réussis).
  • Pour chaque défi réussi : le flag + la méthode en 2 phrases (quel outil, quel onglet, quelle manipulation).
  • Une capture d'écran d'au moins un flag révélé grâce à une modification en direct (Défi 2, 3 ou 6).
  • Bilan sécurité (10 lignes) : pourquoi tout ce qui se passe dans le navigateur (HTML, CSS, JS, cookies, paramètres d'URL) doit toujours être considéré comme visible et modifiable par l'utilisateur ?
